## 2026-07-22 22:04 (channel: #cyber-dev)
- **User:** Tobe retested V2 edit after my v3.2.17 restart. Toast: "Couldn't update quest: quest not found · wanted id \"mlwysbptbii7\", desktop has no quests" — without the expected diagnostic info. He also reported chat/quest step bugs but confirmed the v3.2.19 sync-server fix unblocked the quest edit.
- **You:** v3.2.19 ships the actual fix: the **14-day-old latent bug**. The v3.1.51 commit on 2026-07-08 added 5 new quest-edit message types and 2 diagnostic callbacks (`update_quest`, `delete_quest`, `create_quest`, `set_quest_active`, `mark_quest_goal_done`, `onListQuests`, `onRequestQuestsList`) but **the sync-server constructor never copied them onto `this`**. Only 4 of the ~10 options were stored on `this` (`onChatMessage`, `onVoiceTranscript`, `onAudioInput`, `onAttachment`). The other 7 were left as constructor arguments nobody references. Result: `this.onUpdateQuest ? this.onUpdateQuest(...) : null` always evaluated `this.onUpdateQuest` undefined → `ok = null` → "quest not found" with empty `available`. **The new diagnostic console.logs inside `onListQuests` and `onUpdateQuest` did NOT fire — only the sync-server's outer log fired — which exposed the bug**: the functions in main.js were never being called. The fix: wire up the 7 missing `this.X = options.X || null` assignments in the constructor. Removed the now-unnecessary diagnostic console.logs from v3.2.17 (served their purpose). Also committed v3.10.79 (mobile) for the chat/quest-step fixes Tobe reported. Bumped to v3.2.19. Pushed to origin. See CHANGES_3.2.19.md for the breakdown and the lessons "always test the option-passing contract" + "diagnostic info that itself doesn't work is itself diagnostic" + "a 14-day-old bug is worse than a 14-minute-old bug — when a feature has been failing for a while, the fix has to reach into the foundational layer".
